# PyCARD STAR Protocols Timing Benchmark

This directory contains the reproducible timing benchmark used to
measure the main computational stages of the PyCARD STAR Protocols
workflow.

## Files

-   `timing_protocol.py` --- timing benchmark script.
-   `timing_protocol_results.csv` --- benchmark results generated by the
    script.

The benchmark script is intended to be run from the PyCARD project root.
It automatically adds the project root to the Python import path, so the
`CARD` package can be imported when the script is located under
`benchmark/`.

## Benchmark method

Unless overridden on the command line, each stage is measured using:

-   1 warmup run
-   5 measured runs

For each completed stage, the script records:

-   mean runtime
-   standard deviation
-   minimum runtime
-   maximum runtime
-   number of measured runs
-   number of warmup runs
-   execution status and any error message

Results are saved immediately after each stage so that completed
measurements are retained even if a later stage fails or the benchmark
is interrupted.

## Required benchmark data

The default benchmark uses the files in the project `data/` directory:

-   `spatial_count.csv`
-   `spatial_location.csv`
-   `sc_count.csv`
-   `sc_meta.csv`

CARDfree additionally uses:

-   `markerList.csv`

## Run the standard benchmark

From the PyCARD project root:

``` bash
python benchmark/timing_protocol.py --data-dir ./data
```

The standard run benchmarks the reference-based PyCARD workflow,
including:

-   input data loading
-   reference-based CARD object creation
-   reference CARD deconvolution with the full phi search
-   reference CARD deconvolution with a reduced 3-phi grid
-   reference CARD deconvolution with fixed `phi=0.9`
-   standard quickstart total (`load + object creation + fixed phi=0.9`)
-   scMapping
-   spatial resolution enhancement
-   four visualization functions

CARDfree is not included in the standard run because it is a separate
reference-free workflow and is comparatively long-running.

## Run the standard benchmark including CARDfree

``` bash
python benchmark/timing_protocol.py --data-dir ./data --include-cardfree
```

This runs the standard benchmark and then adds:

-   CARDfree object creation with `nmfSelect=4`
-   CARDfree deconvolution with `nmfSelect=4`

## Run CARDfree only

``` bash
python benchmark/timing_protocol.py --data-dir ./data --only cardfree
```

By default, CARDfree reads `./data/markerList.csv`.

To use a different marker-list file:

``` bash
python benchmark/timing_protocol.py \
    --data-dir ./data \
    --marker-list /path/to/markerList.csv \
    --only cardfree
```

## Run individual benchmark groups

A single group can be selected with `--only`.

``` bash
python benchmark/timing_protocol.py --data-dir ./data --only loading
python benchmark/timing_protocol.py --data-dir ./data --only object
python benchmark/timing_protocol.py --data-dir ./data --only deconvolution
python benchmark/timing_protocol.py --data-dir ./data --only quickstart
python benchmark/timing_protocol.py --data-dir ./data --only scmapping
python benchmark/timing_protocol.py --data-dir ./data --only imputation
python benchmark/timing_protocol.py --data-dir ./data --only visualization
python benchmark/timing_protocol.py --data-dir ./data --only cardfree
```

`deconvolution` measures all three reference-based deconvolution
configurations: full phi search, 3-phi grid, and fixed `phi=0.9`.

`visualization` measures all four visualization functions.

## Run individual visualization benchmarks

The visualization stages can also be measured separately. This is useful
because `CARD_visualize_pie` is substantially longer-running than the
other visualization functions.

``` bash
python benchmark/timing_protocol.py --data-dir ./data --only visualize_pie
python benchmark/timing_protocol.py --data-dir ./data --only visualize_prop
python benchmark/timing_protocol.py --data-dir ./data --only visualize_prop_2ct
python benchmark/timing_protocol.py --data-dir ./data --only visualize_cor
```

## Select multiple groups

`--only` accepts a comma-separated list.

For example:

``` bash
python benchmark/timing_protocol.py \
    --data-dir ./data \
    --only loading,object,deconvolution
```

## Change the number of runs

The default is 1 warmup run and 5 measured runs.

For example:

``` bash
python benchmark/timing_protocol.py \
    --data-dir ./data \
    --warmups 1 \
    --runs 10
```

## Output

By default, results are written to:

``` text
benchmark/timing_protocol_results.csv
```

The script prints the absolute output path at startup and again when the
benchmark finishes.

Each stage is written to the CSV immediately after completion. If a
stage with the same name is run again, its previous row is replaced with
the new result rather than duplicated.

A different output file can be specified with:

``` bash
python benchmark/timing_protocol.py \
    --data-dir ./data \
    --output /path/to/custom_results.csv
```

## Benchmark parameters

The reference-based deconvolution benchmark uses:

-   full phi search: PyCARD default phi grid
-   reduced phi grid: `[0.1, 0.5, 0.9]`
-   fixed phi: `[0.9]`
-   `warm_start_phi=False`
-   `max_iter=200`
-   `epsilon=1e-4`

The scMapping benchmark uses:

-   `shapeSpot="Square"`
-   `numCell=20`
-   `ncore=10`

The spatial resolution enhancement benchmark uses:

-   `num_grids=2000`
-   `in_neighbor=10`
-   `exclude=None`
-   `showGrid=False`

The CARDfree benchmark uses:

-   `nmfSelect=4`
-   `minCountGene=100`
-   `minCountSpot=5`
-   `marker_ct=None`

## Notes on interpretation

Setup operations needed only to prepare an independent downstream
benchmark are performed outside that stage's timed region. For example,
the fitted fixed-phi CARD object used by scMapping, spatial resolution
enhancement, and visualization is prepared before those stages are
timed.

The standard quickstart benchmark is different: it intentionally
measures the complete sequence of input loading, CARD object creation,
and fixed-phi deconvolution.

Runtime depends on hardware, operating system, Python environment,
package versions, dataset size, and system load. The supplied benchmark
data and fixed parameters are intended to make measurements reproducible
and comparable on a specified environment.
